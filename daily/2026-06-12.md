Turned the Odoo connector into a full visual-essay suite using the untrainable scrollytelling format, this time on Tesote colors (black/white/blue instead of gold). Everything lives in `product/automations/accounting-automation/odoo-connector-story/` — read its README before extending; it's the source of truth for beat maps + palette + the screenshot-verification recipe.

**Artifacts (5 essays + README):**

Sourced from [[product/automations/accounting-automation/odoo-prd]] (cockpit PRD). 11 beats: bank truth lives in Tesote → read the whole Odoo graph → categories ≠ CoA → categorize independently → versioned mapping layer → T-1 law → push → what lands → three architectures (Ramp model wins) → pipe-to-cockpit → "Odoo runs the books, Tesote runs the team."

- `carga-bancaria-odoo-es-v1.html` — **the client-facing cut.** Deliberately simplified per my ask: no extraction/architecture talk; just arrives → Tesote verifies (clean + categoría + contraparte) → T-1 overnight → lands in its existing Odoo bank account *listo para conciliar* → config happens once at integration. `tú` voice, zero internal markers. Best line of the piece: "El contador no carga datos: concilia."
- `odoo-connector-story-es-light-v1.html` + `carga-bancaria-odoo-es-light-v1.html` — light-mode variants (white bg, ink text, `#1661E2` accent). The format's signature ending inversion flips the other way: dark finale on light essays. These are probably the right defaults for client shares.

**Decisions / learnings:**

- Palette variants are now a sanctioned part of the visual-essay format: gold for thought-leadership pieces, Tesote black/white/blue (dark or light) for product essays. Saved to memory.
- Versioning discipline: EN/ES and dark/light siblings move in lockstep — any v2 ships as a set, never edit in place.
- "Random link" hosting answer: Netlify Drop — the random `*.netlify.app` subdomain IS the unguessable link; add a `_headers` file with `X-Robots-Tag: noindex` so crawlers don't burn the secrecy. Link-knowledge = access; for truly sensitive stuff, send the file itself. No CLI installs needed.
- Headless-Chrome verification recipe for scrollytelling pages (scroll reveals + vh sizing defeat naive screenshots): throwaway copy forcing `.rv{opacity:1}` + px-pinned section padding, screenshot tall, `display:none` the other sections for per-section shots. Banked in the folder README.

## Late session — marketing pages self-serve lane: shipped the /lp route myself (PR #41)

Asked the "how do we spin up pages fast + safe under tesote.com" question and it turned into shipping actual code to the tesote.com repo — no eng ticket.

**The findings, in order:**

- The fast/safe lane mostly already exists: blog posts + case studies are directory-driven (no routes, no DB; merge → ArgoCD auto-deploys). Dan pointed me at the repo's `post-expert` skill — it runs the whole lane end-to-end, including media-to-CDN uploads (`scripts/uploads/upload`), Kubeez AI images, and a link validator that rejects host-prefixed internal links (so everything published now survives the WordPress→Rails cutover).
- The one gap: **net-new URLs** needed a hand-written `routes.rb` line per page — dev territory per CONTRIBUTING-CONTENT.md. My call: that's a guardrail for marketing, not for me. Shipped it directly.
- **PR #41** — https://github.com/tesote/tesote.com/pull/41 (branch `marketing/lp-dynamic-route`): dynamic `/lp/:slug` route; any template at `pages/static/lp/<slug>.html.erb` is live at that URL, unknown slugs 404; filesystem-driven sitemap entries; `lp/_skeleton.html.erb` copy-source; tests; CONTRIBUTING-CONTENT.md gains a landing-page section. **CI green**, awaiting Dan's merge.
- First CI run failed on Brakeman (dynamic render path — `params[:slug]` in `render`). Fixed properly instead of ignoring: slug resolves through a filesystem allowlist on `RepoContent::Paths` (the repo's existing path-traversal-defense service), so the render path never touches params. Right answer in a fintech repo, and CodeRabbit/Dan see a real remediation.

**Decisions:**

- Prefix = `/lp/` (language-neutral). Renameable until the first page publishes under it — flagged in the PR body for Dan to veto.
- No separate static host (Vercel/Netlify subdomain): fragments SEO, bypasses i18n/analytics, and ingress is Cloudflare Tunnel so eng owns DNS anyway. Rails lane wins.
- Still true: pages land on **marketing.tesote.com** until the WordPress cutover — and cutover is gated on me approving the redesign. That's the real lever for "pages under tesote.com".
