# 2026-06-10

## Mid-session — La Sante SAP integration, phased proposal

Explored offering La Sante a managed data pipeline that pushes their banking data into SAP. They run **SAP R/3 EHP7 for SAP ERP 6.0** (ECC 6.0 EHP7) with a **planned S/4HANA migration in October 2026**.

**Key reframes that shaped the approach:**

- It's **push-only banking data** — no read-back, no reconciliation inside SAP. That means it's just SAP's native **electronic bank statement (EBS) import**, the most standardized path in SAP finance. Not a custom integration. We already do this for [[blueprint-operativo-capca|CAPCA]] (MT940 → S/4HANA) and Ron Santa Teresa.
- **Push-only + manual upload kills the indirect-access licensing landmine.** A human uploading a file via standard SAP transactions is not programmatic indirect access → no SAP digital-access fee exposure on Phase 1.
- **Not a one-off** — other clients have similar SAP setups, so this is a productizable wedge for the SAP cohort, not bespoke SI work.

**The October migration is the natural phase boundary.** No point building deep RFC/BAPI/IDoc plumbing into ECC that gets torn out in ~4 months.

- **Fase 1 (ECC 6.0, now):** Tesote generates **one consolidated MT940** covering all banks/accounts → La Sante uploads manually via transaction **FF.5**. Zero SAP dev, zero licensing risk. The substantial-deal-low-effort phase.
- **Fase 2 (S/4HANA, post-October):** switch to **CAMT.053 (ISO 20022 XML)** — pushed automatically via `API_BANKSTATEMENT_SRV` + `SAP_COM_0316` + OAuth. Luis's call: don't carry MT940 onto HANA; CAMT.053 is the modern native format with richer structured fields (counterparty/reference/remittance) vs MT940's free-text `:86:`. Migration *enables* and *improves* Phase 2 rather than breaking it.

**Format by phase, not one spine:** MT940 on ECC (native, zero-config via FF.5), CAMT.053 on S/4HANA. Both are multi-statement, so one consolidated file holds all accounts in either format. The Tesote data pipeline is reused across the migration; only the output serialization changes (MT940 → CAMT.053).

**Commercial:** sell as a **recurring managed deliverable**, not a one-time build. Near-zero marginal cost per file, continuous value, fast close.
