## Late afternoon — Tesote AI typography + iconography redesign

Pulled the `/ai` design from treasury and turned it into a craft pass. Whole arc fit in one session: dossier → diagnosis → mockup → spec → ticket.

### What I did

- Wrote a comprehensive design dossier of `/ai` as it ships today: [[product/ai/tesote-ai-design]]. Covers system prompt (the 605-line Spanish one), op protocol, 4 zones, 3-layer architecture, 7 security invariants, full file map. This becomes the canonical "what does /ai look like as of 2026-05-20" reference.
- Diagnosed why the current `/ai` feels stronger than Claude Desktop / ChatGPT / Mercury when you put them side-by-side. Root cause: **Inter Tight** (a headline cut, narrower letters, designed for chrome — not body) + 600/700-weight headers + 1.5 line-height. The whole surface reads "control panel" instead of "thoughtful collaborator."
- Built a 3-variant comparison: current vs Inter + Instrument Serif vs Geist + Instrument Serif. Same content, same palette, same layout — only type changes: [[product/ai/typography-comparison.html]]. Squint test made the answer obvious.

### Decisions locked

- **Sans**: Inter at default width (NOT Inter Tight). Zero migration cost — already loaded, just drop `+Tight` from the import.
- **Serif moment**: Instrument Serif on the empty-state hero ("¿Qué querés ver hoy?"). One gesture of editorial type, nowhere else. The Anthropic move (their Copernicus serif on assistant messages).
- **Mono**: JetBrains Mono stays for file names / tool names / IDs.
- **Body**: 15px / 1.6 line-height (up from 14 / 1.5). The single highest-leverage change.
- **Weight ceiling**: 500. 600 reserved only for sidenav brand mark. 700 forbidden except inline `**bold**`.
- **Iconography**: Lucide React at 1.5px stroke, 16px default. Removes all emoji + symbol-font-as-icon (`☾`/`☀`/`›`/`‹`/`←`/`×`/`📎`/`📚`). `/ai`-specific application of the broader [[feedback_no_emojis]] rule.

### Why this matters

The product story is *chat is the question, working files are the answer*. If chat shouts in Inter Tight at weight 700, it fights for attention with the chart it just generated in the right pane. The redesign makes the chat **recede** so the artifact reads as the deliverable. Mercury, Claude, ChatGPT all do this. Tesote AI today doesn't.

Combined CSS delta to ship: ~50–80 lines. One PR. Same `:tesote_ai_demo` flag the surface is already gated on.

### What I asked for vs what I got back

Then mid-session reported a bug: amounts in the working-file table looked wrong this morning.

Treasury exploration changed all three asks materially:

- **Auto-expand** held up clean — `App.tsx:1599-1652` + `styles.css:2701-2717`, hardcoded `rows={3}` and `max-height: 120px`, `resize: none`. Real gap. Small ticket.
- **"OCR"** turned out to be **partially shipped**. Images already go to Claude vision via `imageVision.ts` (resize → base64 → vision content block). Text-extractable PDFs work via `upload_extractor.rb:101-108`. The actual gap is **scanned/image-only PDFs** — they return `extract_failed: pdf_no_text_layer` at `upload_extractor.rb:103`, with a comment at line 25 explicitly calling out "would be the image-OCR fallback path in a later pass." Interesting find for Dan: `Contracts::PdfTextExtractor:59-61` may already return `method: :vision` on text failure — the plumbing might be partially wired but not surfaced. Reframed the ticket from "enable OCR" (vague) to "OCR fallback for scanned PDFs" (precise).
- **Bug** turned out NOT to be a regression. No `/ai` commits today; last touch was 2026-05-19 18:21 UTC (`81366090b` live-QA pass + vision). The actual bug surfaced via the repro file Luis dropped — `facturas-pendientes-mayo2026.json`. The `table` artifact has `total` + `pendiente` columns typed as `currency` but **no per-row currency code**. Bs 5,445,475 sitting next to USD 870 in the same column with the same formatter. Root cause: the system prompt enforces currency safety on **aggregation** ("never sum across currencies") but not on **display**. `TableRenderer.tsx` has no per-row currency context. The MCP aggregation guard at `mcp_result_serializer.rb:304-316` only fires on `dump_to + template: sum|avg`, never on a plain `table` emission.

### The workflow win

Treasury grounding caught real things:
- Stopped me filing a vague "OCR" ticket for something half-done.
- Stopped me framing the amounts bug as a "what regressed today" hunt — it's a design gap, always existed, only surfaced when the dataset spanned currencies.
- Every ticket has file:line anchors Dan can branch off immediately. Linear even auto-generates the branch names.

Worth memorializing: **when filing eng tickets via brain, always do a treasury read pass first**.
