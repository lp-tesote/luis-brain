# 2026-05-16 — Tier numbering position + Movimientos page redesign (v1 → v4)

## Mid-session — Tier numbering: Tier 1 should be top, not bottom

Short scoped convo on customer tiering. Started as a recommendation request ("what tiering system should we go with") and pivoted once I mentioned eng had recently inverted the convention — Tier 1 = bottom, higher = more strategic. I have personal friction with that every time I look at it and wanted Claude's independent take regardless of mine or eng's opinion.

### Claude's position (which I agree with)

**Tier 1 = top.** Reasons:

1. **External gravity.** Every CS playbook, Gartner report, sales book, peer-company doc, and exec hire uses Tier 1 = strategic. Inverting = permanent translation tax on every new hire, board deck, investor convo, benchmark.
2. **Linguistic load.** "Tier 1" naturally reads as primary/best — Tier 1 city, Tier 1 capital, Tier 1 VC. The brain doesn't fight it. It fights the inverted version (I'm proof).
3. **Where eng's instinct came from.** Tier 1 = bottom is the **support-tiering** convention (front-line, escalation goes up). Valid for workflow escalation, wrong for strategic ranking of entities. Probably imported by muscle memory without noticing the domain switch.
4. **CEO friction = signal.** If I have to do mental gymnastics, every exec hire will too.

### The compromise

If eng has a code/DB reason for ascending = more strategic, keep it **in code** as `tier_weight` or `strategic_score`. Business-facing label stays Tier 1 = top. Don't leak an internal sort order into the business vocabulary.

### What I'm doing with this

Not raising today. Saved my position in [[../drafts/tier-numbering-convention]] so I can pull it up when I bring it to Dan / eng. The draft has the four reasons, the in-code compromise, and three open questions to anchor the convo (how widely is the inverted convention already in use, what's eng's actual reason, migration cost).

The longer this sits, the harder the flip — so raise it before too many surfaces calcify around the inverted version.

## Late session — Movimientos page redesign: naming → v4 prototype with full filter system

Continuation of the Connect redesign work after Saldos (2026-05-14). Today's target: the transactions ledger. Same playbook — name first, design.md decisions, ASCII, then iterate HTML through versioned siblings. Four prototypes shipped: v1 (base) → v2 (truncation + last-4) → v3 (Mercury-style filters + Envía column) → v4 (full 11-dim filter system + saved views + totals fix).

### Naming locked: Movimientos (not Transacciones)

Same logic as Saldos over Cuentas — **job over object**, **native vocabulary over imported ERP language**. Every VE bank app says "movimientos" in the extracto. Pairs with Saldos as the Connect ledger couplet: *Saldos = where I stand. Movimientos = what moved.*

Tension flagged but doesn't kill it: when Tesote becomes system-of-record per the command-center thesis, this page may surface non-bank-pulled rows (manual journal entries, internal transfers). "Movimientos contables" is the Spanish accounting term for journal entries too, so the name scales.

### Column set (locked v2 onwards)

```
Fecha · Banco/Cuenta · Descripción · Contraparte · Monto · Categoría · Envía (✈)
```

6 data columns + paperplane action. Key calls:

- **Banco/Cuenta merged** into one cell — `LOGO · BNC · Ops VES ··5421`. Two columns would waste pixels; the cuenta tells you the bank. Last-4 in monospace gray-3 disambiguates same-bank same-flavor accounts.
- **Description anchor with truncation** — fixed-width column, `text-overflow: ellipsis`, native title tooltip on hover, full text in drill-in. Row height **never** breaks. Top products (Mercury / Linear / Stripe / Airtable / Brex / Ramp) all converge on this pattern. **No fade-out, no two-line clamp** — ellipsis is the safer call for a reconciliation surface.
- **Em-dash `—` for null Contraparte / Categoría** — not "Sin contraparte". Less wordy at 36px. Tooltip clarifies "click para asignar".
- **Inline-edit on Contraparte + Categoría** — Mercury-style click-to-dropdown, in v1. Current UI already supports it; keep parity.

### The paperplane — load-bearing design choice

Replaces Mercury's attach-invoice `+` column with a **send-out** affordance:

- Always-visible (not hover-only, after v1 → v2 feedback that hover-reveal made the CTA undiscoverable)
- Click → modal stub: destinatario field + Email/WhatsApp/Link channel toggle + mensaje
- Use cases: "here's the wire we received from you" (confirmation to a payer), "we just paid your invoice — here's the proof" (confirmation to a payee), share with a teammate, future "request categorization" from recipient

**Strategic framing:** this is Tesote-as-system-of-action. Banks pull data *in*; Tesote pushes structured movimientos *out*. Mercury attaches receipts because their users do AP. Tesote sends because Tesote is the action layer on top of the data.

### Data certification — killed from the row for v1

Earlier on Saldos (2026-05-14) we decided certification belongs on Transacciones not Saldos (saldos are 99% reliable, tx completeness is the real concern). On Movimientos itself, I opted to **kill it from the row anatomy for v1** — re-evaluate as filter pill or dedicated reconciliación view. Worth revisiting once we have real conciliación data to anchor the badge against.

### Mercury-style filter builder (v3 → v4)

v3 introduced the pattern (single `+ Filtrar` button → dim picker → dim input → pill), v4 built out **all 11 dimensions Luis spec'd**:

`Fecha · Bancos · Entidades · Cuentas · Contrapartes · Categorías · Moneda · Monto · Descripción · Nota · Referencia`

Notable per-dimension choices:

- **Fecha** is the only "wide" popover (540px) — two panes, presets left + 2-month calendar grid right with click-to-set range + typed Desde/Hasta inputs. 11 presets covering all the easy options (Hoy / Esta semana / Este mes / Este trimestre / Este año / Semana pasada / Mes pasado / Últimos 30 días / Últimos 90 días / Trimestre pasado / Todo el tiempo).
- **Monto is composite** — Tipo radio (Cualquiera/Crédito/Débito) + Cantidad radio (Cualquier/Exacto/Rango) with conditional reveal of one or two numeric inputs. Combines multiplicatively. Pill renders as `Monto · Crédito · ≥ 1.000`.
- **Referencia** is a segmented Contiene/Exacta toggle + text input.
- **Default Fecha = Últimos 30 días** on page load. Removable. Backend should hint "Todo el tiempo" is heavier.
- **Saved views** — `localStorage`-persisted named filter combinations (`tesote.mov.savedViews.v1`). Click a view to apply, × to delete, "Guardar vista actual" with name input. Server-backed in production.

Filter spec fully written in `design.md` under "Filter system (full spec)" — engineering can implement directly from there.

### Totals strip rebuilt — handles 10-digit Bs / 9-digit USD

Luis caught the horizontal layout breaking on real-scale VES amounts (sent a screenshot of `+Bs.` wrapping to its own line above `3.700.000,00`). **Switched to stacked layout** per card:

- Three rows per currency card: Ingresos · Egresos · Neto
- Label-left (90px column) + amount-right (tabular nums, nowrap)
- Neto separated by solid divider, slightly larger amount font (20px vs 18px)
- Green for credits, neutral for debits

Guarantees the layout never breaks regardless of digit count. Should be the **default for all currency totals strips** going forward — same fix probably applies to Saldos at scale.

### Table-padding tokens promoted to archetypes.md

Calibrated against the two real tables we've shipped (Saldos = Manage / 44px, Movimientos = Browse / 36px). Added a per-density-bucket reference table:

| Density | Row | `th` v / h | `td` v / h |
|---|---|---|---|
| Browse | 36px | 10/14 | 7/14 |
| Manage | 44px | 12/16 | 11/16 |
| Review | 52px | 14/18 | 15/18 |

Rules locked: th/td horizontal padding must match exactly within a table (or column edges visually drift); per-column horizontal overrides allowed but must apply to BOTH th and td of the column. Replaces the existing `8 / 14 / 19` one-liner that was theoretical and would have produced 52px rows at browse density.

- **v1 feedback:** widen Banco/Cuenta + last-4 / description truncation pattern / em-dash placeholder / always-visible paperplane / `Envía` header / Mercury-style filters
- **v2 feedback:** Contraparte 170→220px / `Envía` header / functional Mercury-style filters / padding consistency question (→ promoted to archetypes.md)

Recalibrated the proposal and acknowledged the miss directly.

### Decisions locked today

1. **Naming:** Movimientos (over Transacciones)
2. **Date format in rows:** `DD/MM` for current year, `DD/MM/YYYY` for prior year
3. **6 default columns + Envía paperplane trailing action** — paperplane is always-visible, sends/shares-out the row (not Mercury's attach-in pattern)
4. **Description truncation:** table-layout fixed + ellipsis + tooltip + drill-in for full text. Row height never breaks. **No wrap, no fade-out, no two-line clamp.**
5. **Em-dash `—` for null Contraparte / Categoría** (not "Sin contraparte")
6. **Inline-edit on Contraparte + Categoría** — Mercury-style, v1
7. **Cert badge killed from the row for v1** — re-evaluate later
8. **Filter system:** Mercury-style builder, 11 dimensions, calendar + presets, combined Monto (Tipo + Cantidad), Referencia exact/contains, saved views
9. **Totals strip:** stacked layout (handles 10-digit Bs / 9-digit USD)
10. **Table-padding tokens promoted system-wide** — see [[../product/design/archetypes#table-cell-padding-per-density]]

### What worked, what to remember

- **Versioned prototype siblings** (v1 → v4) preserved exploration without losing state. Same pattern as Saldos. Per [[feedback_versioning_progression]].
- **Spec inline in design.md** (vs separate filters-spec.md) — kept everything in one place; the engineering handoff can pull from one doc. Worth keeping unless the spec doc grows past readable.
- **Calibrating system-wide tokens against real prototypes** (padding numbers came from Saldos + Movimientos actuals, not theoretical guesses) — caught the existing archetypes.md numbers being wrong. Same loop: ship one real table, extract tokens back.
- **Luis correcting me on Mercury** mid-session was useful — I was running on a stale mental model. Lesson: when claiming a top product does X, verify against actual screenshots before basing recommendations on it.
