# 2026-05-25

## Session — Automations builder: reconciling bank fees (v0.1 mockup)

Picked up directly from the [[2026-05-24|2026-05-24 taxonomy work]]. That session's punchline was: *the Automations surface doesn't exist yet but the taxonomy demands it.* Today is the first stab at what "putting together an automation" actually looks like on screen — with the simplest possible workflow as the unit test: **categorize bank fees**.

### Framing decisions (made before sketching)

1. **Builder shape — hybrid: chat proposes → structured form refines.** Not a workflow-canvas (n8n-style), not a pure form, not a chat-only setup. Reason: this is the same Harvey/Legora "speak like the user, output structure" pattern in [[project_winning_vs_horizontal_ai]]. The user types intent in plain Spanish; Tesote AI returns a *structured, citable, verifiable* rule. Form view exists for the 20% case where they want to twist a knob.
2. **Scope — categorize-only.** No matching against expected fees, no fee-family handling. Reconcile-bank-fees = simplest possible automation, on purpose. The point of this mockup is to validate the *construction mechanic*, not the recon depth.
3. **Output — HTML mockup, in the locked /ai design family.** Same tokens as [[../product/ai/use-case-taxonomy-v0.1|use-case-taxonomy-v0.1]] (Inter + Instrument Serif + JetBrains Mono, 15/1.6, weight ≤ 500, Lucide SVG inline, no emojis, Venezuelan `tú`).

### The 5-frame flow

1. **Pantalla vacía** — composer-as-only-entry, suggested-prompt chips, empty `Reglas activas` list. Bet: no "New rule" modal button; the composer is the single ingress.
2. **AI propone la regla** — user types "Categoriza las comisiones bancarias" → 2s → structured rule card. VE-specific tokens (`COMIS`, `MANT CTA`, `IGTF`, `COM TRANSF`), 47 historical matches counted, mode toggle (Autopilot / Borrador), primary "Activar". This is the wow.
3. **Inspeccionar matches** — table of the 47, per-row "Excluir" escape hatch. Dry-run before commit. One excluded row shown (a reverso that isn't actually a fee) — the kind of detail Mercury/Brex rule-builders miss.
4. **Refinar (forma estructurada)** — same data tree, all knobs exposed: conditions list with operators, Odoo account picker, schedule, mode. Most users never open this; the 20% that do can scope to one bank, change the GL account, etc.
5. **Activada** — success banner, rule lives in `Reglas activas (1)`, live activity strip showing the first fire. Composer reappears asking "¿Qué más automatizamos?" — closes one loop, opens the next.

### The non-obvious design bets

- **Composer is the only entry.** Hypothesis: most useful automations can be derived from history → system *proposes*, user *refines*. Risk: some controllers want an explicit blank "New Rule" form. Worth a gut-check with Mariel.
- **Tokens at Estado 02 are a rendered view of the form at Estado 04** (same data tree, two presentations). Means: editing the proposal == editing the structured rule. No translation layer.
- **Always-visible row actions** on the active-rule list (per [[feedback_always_visible_affordances]]) — view / edit / pause / more all rendered at rest, primary on hover.
- **Live activity strip after activation.** Not just a settings row — a *thing that's running*. That visible "live" signal is what separates "automation" from "preference toggle" in the user's head.

### Open questions for the next session

- **Exclude-row semantics.** I made the 3 exclusions sticky to the rule (those reversos are never touched). Alternative: exclusions only affect dry-run, the live rule re-evaluates from scratch. Different mental model — I lean sticky because it matches the trust contract ("you saw 44, you'll get 44"), but worth talking through.
- **Activity strip vs. Actividad tab.** I show both. Could collapse to a tab-badge to reduce surface area on the home screen.
- **Mode default = Autopilot.** Aggressive. Worth checking if first-time users want the default flipped to Borrador for safety.
- **Sugerencias chips below the composer.** Listed: CANTV → Telefonía, Alquileres, Nómina, Transferencias entre cuentas propias. Need to validate these are actually the next 4 most-painful rules a Tesote customer would want — derive from real bank-feed data, not guess.
