### The local-setup problem

My machine has **none** of the prerequisites:

- No Homebrew
- No Ruby version manager (mise/asdf/rbenv) — system Ruby is 2.6.10, repo wants 4.0.3
- No Docker
- No Bun

I genuinely don't dev locally — I drive everything through Claude. So installing all of that (~5GB, 30-60 min, ongoing maintenance) is a real decision, not a default. Three paths surfaced:

1. **GitHub Codespaces** — cloud dev env, zero local install, runs in browser/VS Code. Likely cleanest for both me and the designer (easy to revoke). Need to confirm it's enabled on the org.
2. **Full local install** — Homebrew → mise → Ruby 4.0.3 → Bun → Docker Desktop. Powerful but heavy.
3. **github.com edits only** — works for tiny copy tweaks; useless for actual design work.

## Late evening — Tesote AI MCP limitation surfaced via live use → ENG-4016

Ran a live Tesote AI conversation against the prod MCP asking a basic analytical question — *"qué porcentaje de transacciones están categorizadas en 2026?"* — and it failed quietly until I pushed. Worth filing because **this is the first wall every customer will hit** the moment we widen the rollout to finance teams (per [[../marketing/tesote-ai-rollout-plan]] and the audience reframing in PRO-163).

### What broke

The `tesote-workspace.transactions.search` MCP tool:

- Returns an envelope `{ items, returned, total, has_more, next_cursor }` — i.e. **already shaped for pagination**.
- But the **input schema has no `cursor` / `offset` / `page` parameter** to consume `next_cursor`.
- So the tool is hard-capped at the latest 100 rows, ordered by date desc, with no escape hatch.

Pagination is half-built, not missing. That's the real root cause — and the cheaper fix because the response side is already there.

### How it failed in conversation

1. AI answered "84% categorizado" off the latest 100 tx (14–22 May only) — **no `total` / `has_more` caveat in the first reply.**
2. I asked for per-month breakdown. AI did one call per month → reported 86–96% across Ene–May → "promedio del año ~90%."
3. Each per-month call also hit the cap. AI didn't notice until I asked *"how do you know you're getting all the movements? what if we have 500+/month?"*
4. Then it admitted: *"no lo sé… el endpoint no tiene parámetros de page ni offset."* Recommended I export CSV from the dashboard or query Odoo's `account.bank.statement.line` instead — which defeats the point of the workspace MCP.

So there are **two gaps**, not one:

- **MCP backend (ENG-4016, this ticket):** add cursor input param. Envelope's already there; close the loop.
- **Agent behavior (sibling, not yet filed):** when `has_more: true`, the AI should paginate proactively *or* refuse confident aggregates — not return a number first and only caveat under cross-examination. This is the user-visible failure mode.

## Late night — Finance: dev-capacity investment scenarios (pre-read for Dan)

Prep for the financials chat + team planning meeting. Core decision on the table: **do we spend an extra $10–30k/mo on devs/PMs to ship faster and grow revenue faster, and do we fund it from cash or raise a small round?**

### The numbers I cleaned up

- Subscriptions (active + paying only, churned removed): **~$98k/mo**
- Implementation fees (May): **$16.5k**
- Expenses (incl. ~$10k salary bump): **~$135k/mo**
- Burn ~$20.5k/mo, cash **$480k** → 20+ months runway. Operating-only, no intercompany.

### The reframe (the actual insight)

It was never "devs vs. no devs." It's **"if we turn on AI-driven demand, can we deliver against it — or do we leak it?"** Delivery capacity is the binding constraint on capturing AI revenue. AI wins customers; if we can't build/onboard fast enough, they churn and we've paid to acquire customers we then lose. So devs = **capture vs. leak**, worth ~$60–75k/mo of revenue protected by year-end, growing. That's a far stronger case than "more velocity."

### Scenarios (9, 12-month: May '26 → Apr '27)

Built across 3 growth drivers (Baseline +$7k MRR/$10k IF; AI +$10k/$13k; AI+Payments +$13k/$16k from Sep; Stall +$3.5k/$7.5k) × hiring on/off. Key findings:

- **We survive every scenario except one.** Business isn't fragile.
- The one danger: **stall + full devs** → stuck ~8mo runway, dips <$100k Q3 '27. Only cell that forces a raise-from-weakness or hard cut.
- **Recommended = the staged path:** add **$10k/mo now**, hold through summer, **September decision gate** — ramp to $25k if AI is working (we *have* to, or we leak), stop if not (only ~$30k at risk). Staging *dominates* hiring the full team in June: same end team + revenue, but higher cash floor ($409k vs $394k) and more ending cash ($565k vs $550k), plus keeps the option. No version where full-June-ramp wins.
- Raise ($250–300k at $10m+, ~3% dilution) is **optional/decoupled** — only needed if we go un-cuttable FTE or want the cushion fully intact.

### WHY staged

Caps downside (only $30k risked to the Sep gate) without giving up the upside, and lets us decide with 3 months of real data instead of faith. Hire cuttable (contractors/probation) so the stop-or-go is real; stall trigger = if new MRR tracks +$3.5k not +$10k by August, freeze.
