## Ops — claudetm setup for pushing PRs to prod

VP-eng message: "set up `developerz-ai/claude-task-master`, ask Claude to install it, do your changes, run `claudetm merge-pr`." **Paused — it had every hallmark of a phishing / supply-chain lure:** name-squat of the popular OSS `eyaltoledano/claude-task-master`, unknown org, "ask Claude to install it for you", "just run this one command", and the named command (`merge-pr`) wasn't in the public docs. Wanted my Claude OAuth creds + authenticated `gh` — exactly what you'd steal to push malicious code as me.

**Verified out-of-band with Dan via Slack** (didn't reply on the original thread). Dan confirmed it's **genuinely ours** — we built it. *Lesson for next time: any "install this dev tool" message gets trust-channel verification before anything runs, regardless of who it claims to be from.*

**Then set up (bare machine — no brew/uv/pip/gh going in):**

- Homebrew (I downloaded the installer to `~/`, Luis ran it locally — needs macOS password)
- `brew install uv gh`; `uv tool install claude-task-master` → `claudetm` in `~/.local/bin`, own Python 3.12 (not system 3.9)
- `gh auth login` over SSH — used existing `~/.ssh/id_ed25519` (already had one, did NOT regenerate), account `lp-tesote`
- brew `shellenv` → `~/.zprofile` for persistence

**macOS credential gotcha (the real blocker):** `claudetm` only reads `~/.claude/.credentials.json`, but Claude Code on macOS keeps the OAuth token in the **Keychain** — so that file never exists. Fix = `security find-generic-password -w -s "Claude Code-credentials" -a luispulgar > ~/.claude/.credentials.json`. **One-time snapshot — goes stale when the token rotates; re-export to fix.** `claudetm doctor` now all-green.

**`merge-pr` is autonomous, not a plain merge:** monitors PR → fixes CI + review comments *with Claude* (writes/pushes code as me) → resolves conflicts → merges, loops up to 30x. → **First live run in `treasury` will use `--no-merge`** to eyeball changes before they hit the base branch.
