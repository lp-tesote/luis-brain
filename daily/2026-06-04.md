# 2026-06-04 — AI usage queries for Metabase

## Session — AI usage Metabase queries (schema orientation + per-user query)

Wanted visibility on Tesote AI adoption. Mapped the AI surface in the Finance DB and wrote the queries to run as native SQL questions in Metabase.

**Data model (what Metabase sees):**

- `ai_conversations` — one row per chat/job. `subject_id` → `workspaces.id` (subject_type always `'Workspace'`). Key column: `workspace_user_id` — **NULL = system job** (e.g. AI auto-categorization via `Tesote::TransactionsCategorizeWithAi`), **set = real human chat**. That split is what makes a "usage" number honest.
- `ai_conversation_messages` — `role` (user/assistant), `content`, `user_feedback_positive` (thumbs up/down), `created_at`.

**Caveat:** the `tesote_notebook/Finance/schema.rb` snapshot is ~46 days stale — predates `title` / `workspace_user_id` on `ai_conversations` (added with the chat rollout). Production behind Metabase has them. Verified against live treasury models instead of the snapshot.

**Queries written (run in Metabase, Finance DB):**

1. Weekly AI usage by workspace × user, chat vs system, with thumbs up/down counts (8-week window)
2. Per-user all-time totals — conversations, total/user messages, feedback, first/last message dates. Workspace kept in GROUP BY so same person in two workspaces shows twice; drop `w.name` to collapse.

**Why it matters:** [[tesote-ai-rollout]] adoption signal — who's actually chatting vs one-shotting, and whether system jobs are inflating any "AI usage" topline.

**Next:** run the per-user query, eyeball depth-of-usage (`messages_count` histogram if people look like one-shotters). Worth saving as a pinned Metabase question if the numbers get looked at twice.
