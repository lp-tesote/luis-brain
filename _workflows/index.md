# Workflows

Operating procedures that span tools, repos, or systems. Not "content" (lives in function folders like `product/`, `finance/`, etc.) and not "skills I'm building" (lives in `learnings/`). These are **how Luis + Claude actually get work done**.

## Active workflows

- [Brain → Treasury (implementation bridge)](brain-to-treasury.md) — when a brain doc matures into something that'll become code, run `/tesote-plan` in treasury to translate it into an implementation plan grounded in the codebase.

## Conventions

- One file per workflow. Short, scannable, decision-oriented.
- Each workflow names: the trigger, the steps, the artifacts, the related skills/memories.
- Update in place when the workflow evolves — these aren't decision logs, they're current state.
- Cross-link to function-folder docs and memory entries via `[[wiki-links]]`.

## Discovery surfaces

- `CLAUDE.md` → "Relationship to treasury (implementation bridge)" points at the brain → treasury workflow.
- Future workflows that codify cross-cutting procedures (brain → KB, ticket-filing, PRD-to-ship loop, etc.) accrete here. CLAUDE.md should link to them as they land.
