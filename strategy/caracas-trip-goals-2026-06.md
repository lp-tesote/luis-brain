# Caracas Trip Goals — 3 Weeks

**The point of being on the ground:** the whole team is in one place for the first time around launch. Use the three weeks for the things that *only* happen in person — decisions, owner assignments, hard conversations — not the things that happen over Slack anyway.

**The spine:** **Reverón ships July 1, inside this window.** Everything sequences around that. Trip ≈ launch run-up → launch → convert. (Weeks below are relative to launch; pin exact calendar when start date is fixed.)

**One sentence per stream — what "won" looks like by the time I fly out:**

1. **Reverón** — Launched on time, and week-1 usage is already converting to upsell (not just "it shipped").
2. **Bank API transition** — Stopped being a draft. It's a *running machine* with an owner, a process, and a pricing answer — and batch-1 priority accounts are migrating.
3. **Finance overhaul** — The $250K line is committed and the SAFE raise is live. I stop running at the reserve floor.

## 1. Reverón Launch — *ship + convert*

North star: this is the AI land-grab. Launch is the start of the upsell motion, not the finish line. ([[project_ai_launch_master_plan]]: give → watch → bucket → upsell; usage telemetry is the engine.)

**3-week definition of done:**
- [ ] **Launch date locked** (currently "July 1, not formally locked") — pick it Week 0, work backward
- [ ] Shipped July 1 — day-one scope = **Tesote MCP only** ([[project_ai_launch_day_one_scope]]); 7-behavior launch contract met
- [ ] Client **FAQ doc written** (flagged as a gap) + domain purchased (flagged, still open)
- [ ] Vero's staggered teaser sequence executed (email + WhatsApp, *not* same-day blast)
- [ ] **Usage telemetry live on day one** — if I can't see who's using what by EOD July 1, the upsell motion is blind
- [ ] Week-1 readout: users bucketed, first upsell conversations opened ("100% upsell week 1" is the stated bar)

**Sequencing:**
- *Week 0 (run-up):* lock date, finish FAQ, buy domain, dry-run teasers, confirm telemetry instrumented. File any remaining P1/P2/P5 sev tickets ([[project_ai_pitch_launch_narrow]]).
- *Week 1 (launch):* ship July 1, teasers fire on cadence, watch usage.
- *Week 2 (convert):* bucket users, run upsell conversations, log what's missing → next PRD wave (Odoo MCP = wave 2).

**Owners:** Vero (launch comms), Majo (product), Dan/eng (ship + telemetry), Luis (date call, upsell narrative).

**Risk to kill early:** launch date never gets formally locked and slips. Make that the Week-0 decision.

## 3. Finance Overhaul — *off the reserve floor*

North star: stop running at zero buffer. The plan is written and self-contained ([[finance/financial-operating-plan-2026-06.md]]); the trip is where it gets *executed*. Structural problem = **$80K/mo USD shortfall**, 45–60d Bs→USD conversion cycle, breakeven ~Dec.

**3-week definition of done:**
- [ ] **$250K credit line committed on the US entity** — the single highest-leverage action. Even at ~$0 first draw, it must be *available*.
- [ ] **SAFE raise launched** ($250–400K) — framed as buffer + downside insurance, not routine burn. Target buffer $150–250K above the $400K reserve.
- [ ] **Confirm current USD cash balance** — sets the first-draw date (est. July)
- [ ] **Monthly tracking dashboard live** — the 6 trigger metrics (USD position, trailing-3mo burn, % USD revenue, conversion cycle, line drawn, breakeven tracking)
- [ ] Measure **actuals**: days-to-collect + days-to-convert, payment-cadence mix (monthly vs. quarterly drives the float case)

**Sequencing:**
- *Week 1:* confirm USD balance + cadence mix (data I need before anyone says yes); open line conversation.
- *Week 2:* line committed; SAFE materials out to investors.
- *Week 3:* dashboard live, first monthly review run against it.

**Structural levers to push in parallel** (these lift the ceiling, not just patch the gap): grow USD-denominated revenue, smooth billing toward monthly cadence.

**Risk to kill early:** "raise the SAFE" stays vague. The line is the concrete first move — it's available capital, not dilution. Land it first.

## How the three connect

- **Reverón** is the revenue engine for the 10x — and a Reverón upsell that's USD-priced directly helps the **finance** gap (grow USD revenue = #1 structural lever).
- **Bank API transition** is what makes the product reliable enough that Reverón/Connect don't break — it's the foundation under the launch.
- **Finance** buys the runway to do both without running at the reserve floor.

If I had to rank by "only happens in person": **Bank API ownership decision** (Week 1, in the room) > **Reverón launch-date lock** (Week 0) > **finance line/SAFE** (can progress remotely but faster face-to-face with the team + investors).
